### 2. Core Mission Directive

You will develop an "AI-Powered Agriculture Crop Advisory Assistant"—a comprehensive platform designed to help farmers and agricultural workers diagnose crop diseases, optimize yield, and manage farm operations using generative AI.

### 3. Product Goal

To provide a reliable, localized, and intelligent web application where users can manage their farm profiles, log crop cycles, and receive real-time, AI-generated agricultural advice powered by Google's Gemini models.

### 4. Mandatory Features

* **Secure Authentication**: JWT-based user registration and login.
* **Farm & Crop Management**: CRUD operations for managing farm profiles, individual fields, and active crop cycles.
* **AI Advisory Engine**: A dynamic form interface to submit crop symptoms (e.g., visual descriptions, soil conditions, weather patterns) to the Gemini API for actionable remediation plans.
* **Advisory History**: Persistent storage of past AI interactions, tied to specific fields and crops for historical tracking.
* **Responsive UI**: A fully mobile-responsive, accessible dashboard built with Tailwind CSS.

### 5. Technology Requirements

* **Frontend**: React.js (Vite), React Router DOM, Tailwind CSS, Lucide React (for icons).
* **Backend**: Node.js, Express.js.
* **Database**: Replit Postgres (PostgreSQL).
* **AI Integration**: `@google/genai` SDK (Strictly use the new Google Gen AI SDK).
* **Validation & Typing**: Zod.
* **State & Fetching**: React Context or standard fetch API with React hooks.

### 6. Application Pages (Routes)

* **`/` (Landing Page)**: Hero section, features overview, and call-to-action to login/register.
* **`/login` & `/register**`: Authentication forms.
* **`/dashboard`**: High-level overview of the user's farms, active crops, and recent AI advisories.
* **`/farms`**: List of all farms.
* **`/farms/:id`**: Farm details, including associated fields.
* **`/crops/add`**: Form to register a new crop to a field.
* **`/advisory/new`**: The AI Advisory Engine form interface.
* **`/advisory/history`**: Paginated history of past AI diagnoses and reports.

### 7. User Flow

1. User arrives at the Landing Page and registers an account.
2. User navigates to the Dashboard and is prompted to create their first Farm profile (e.g., location, soil type).
3. User adds Fields to the Farm, and logs current Crops.
4. User encounters an issue (e.g., yellowing leaves on tomato plants).
5. User navigates to the AI Advisory Engine, selects the specific farm/crop context, inputs the symptoms, and submits.
6. The Backend routes the query to Gemini, applying context and system instructions.
7. Gemini returns a structured JSON response (Diagnosis, Action Plan, Risk Level).
8. The backend saves the advisory record to Replit Postgres.
9. The UI displays the formatted AI response to the user.

### 8. Target Domains & Categorization

* **Pest & Disease Diagnosis**: Identifying pathogens based on visual descriptions.
* **Nutrient Deficiency**: Identifying soil issues (e.g., Nitrogen/Potassium deficiency).
* **Weather Remediation**: Frost, drought, or flood recovery plans.
* **Yield Optimization**: General advice on fertilizer scheduling and irrigation.

### 10. Database Schema (Production SQL for PostgreSQL)

Execute this schema exactly for Replit Postgres:

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE farms (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(255) NOT NULL,
  location VARCHAR(255),
  soil_type VARCHAR(100),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE crops (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  farm_id UUID REFERENCES farms(id) ON DELETE CASCADE,
  crop_type VARCHAR(100) NOT NULL,
  variety VARCHAR(100),
  planting_date DATE NOT NULL,
  status VARCHAR(50) DEFAULT 'ACTIVE',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE advisory_records (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  crop_id UUID REFERENCES crops(id) ON DELETE CASCADE,
  symptom_query TEXT NOT NULL,
  ai_diagnosis TEXT NOT NULL,
  ai_action_plan JSONB NOT NULL,
  risk_level VARCHAR(50),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

```

### 11. Row Level Security (RLS) / Data Isolation Rules

Since this uses standard PostgreSQL via Express.js, implement strict tenant isolation in the backend API queries. EVERY query to `farms`, `crops`, and `advisory_records` MUST include a `WHERE user_id = $1` clause utilizing the authenticated user's ID decoded from the JWT.

### 12. Backend API Routes

* **POST `/api/auth/register**`: Hash password with bcrypt, insert user, return JWT.
* **POST `/api/auth/login**`: Verify password, return JWT.
* **GET `/api/farms**`: Retrieve user's farms.
* **POST `/api/farms**`: Create farm.
* **GET `/api/crops**`: Retrieve user's crops.
* **POST `/api/crops**`: Create crop.
* **POST `/api/ai/advise**`: Accept form data, construct Gemini prompt, fetch AI response, save to `advisory_records`, return response.
* **GET `/api/advisory**`: Retrieve user's past advisories.

### 13. Gemini SDK Setup & Server-Side Security

* Use the new SDK: `npm install @google/genai`
* Initialize securely on the server-side only:
```javascript
import { GoogleGenAI } from '@google/genai';
const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

```


* Never expose `GEMINI_API_KEY` to the frontend.

### 14. AI System Prompt

Inject this instruction into the Gemini API call using the `systemInstruction` parameter:

You must output all responses in strict JSON format. Include necessary disclaimers that you are an AI and physical soil testing is recommended."

### 15. Detailed AI Prompts (with required JSON Schemas)

When calling `ai.models.generateContent`, enforce this JSON Schema using `responseSchema` and `responseMimeType: "application/json"`:

```json
{
  "type": "object",
  "properties": {
    "diagnosis": { "type": "string", "description": "The likely cause of the issue." },
    "risk_level": { "type": "string", "enum": ["LOW", "MODERATE", "CRITICAL"] },
    "action_plan": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {

}

```

### 16. Zod Validation Requirements

Use Zod on the Express backend to validate all incoming requests:

* `RegisterSchema`: Email must be valid, password min 8 chars.
* `FarmSchema`: Name string > 2 chars, soil_type optional string.
* `AdvisoryQuerySchema`: `crop_id` UUID, `symptom_description` min 10 chars, `growth_stage` enum.
